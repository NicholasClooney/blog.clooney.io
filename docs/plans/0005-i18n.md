# 0005 — Opt-in multi-language (i18n) support

Status: in progress on `feat/i18n`. Requested by the downstream blog (blog.clooney.io) to ship a Simplified Chinese version.

## Content contract (stable; downstream content is written against it)

Language codes below use `zh` as the example. Any code listed in `site.i18n.languages` works the same way.

### Turning it on (`_data/site.yaml`)

```yaml
i18n:
  enabled: true          # default false: site builds exactly as before
  defaultLanguage: en    # stays at the current, unprefixed URLs
  languages:
    - code: en
      label: English
      htmlLang: en
    - code: zh
      label: 简体中文
      htmlLang: zh-Hans
```

### Where translated content goes

| Original | Translation | URL |
|---|---|---|
| `posts/**/<slug>.md` (`/posts/<slug>/`) | `zh/posts/<slug>.md` | `/zh/posts/<slug>/` |
| `notes/<slug>.md` (`/notes/<slug>/`) | `zh/notes/<slug>.md` | `/zh/notes/<slug>/` |
| `notes/hidden/<slug>.md` (`/notes/hidden/<slug>/`) | `zh/notes/hidden/<slug>.md` | `/zh/notes/hidden/<slug>/` (still hidden) |

- The file slug MUST match the original's slug. That is how a translation is paired with its original (same URL after the `/zh` prefix). No translation key is needed.
- Timeline entries are not translated. Do not create `zh/timeline/`.
- Assets/images: reuse the English post's files. If the original uses a relative path, rewrite it as the site-absolute path to the same file (the translation lives in a different folder, so copied relative paths break).

### Front matter

```yaml
title: 中文标题
date: 2026-04-14       # same date (and `time`, if the original has one) as the original
tags: [same, topic, tags, as, the, original]   # keep tag slugs in English
excerpt: 可选          # optional, as for English posts
draft: true            # optional, same meaning as today
```

Do NOT set `lang`, `permalink`, `layout`, or the `posts`/`notes` content tags. They are derived from the `zh/` folder by the builder.

### Per-language UI strings

One file per language: `_data/locales/zh.yaml`. Every key is optional; anything missing falls back to English.

```yaml
ui:          # same shape as _data/ui.yaml, deep-merged over it
  shared:
    pagination:
      previous: 上一页
nav:         # sidebarNav item id -> label
  blog: 博客
  notes: 笔记
series:      # series id -> title / intro overrides
  subspace-builder:
    title: Subspace Builder 系列
    intro: ...
site:        # optional site-level overrides
  title: ...
  description: ...
```

## Behaviour decisions

- English stays at current URLs; nothing moves. Second language lives under `/<code>/`.
- Language switcher only appears on pages that have a counterpart. Listing/section pages always have one when i18n is on.
- `/zh/` listings (home, blog, notes, tags, series) show translated content only. Series pages under `/zh/` link to the translated entry when it exists, else to the English one.
- Timeline: `/zh/` nav links to the English `/timeline/` (no duplicated timeline pages).
- When i18n is disabled, output is byte-identical to today (existing tests and snapshots unchanged).

## Additions after the zh preview (stable)

### Missing-translation link fallback

In a translated page, an internal link to `/<code>/...` whose target has no translation in that language is rewritten at build time to the default-language page (`/zh/posts/x/` → `/posts/x/`), with a build warning. The internal link check then passes. No front matter or config needed.

### AI-translation notice

Shown at the top of translated posts and notes (non-default-language pages), linking to the original page in the default language.

Front matter (on the translated file):

```yaml
translatedBy: ai      # shows the notice; `human` (or omitted) shows nothing
```

Site-wide default (`_data/site.yaml`), optional:

```yaml
i18n:
  translationNotice:
    default: ai       # treat translated pages without `translatedBy` as `ai`; `translatedBy: human` opts a page out
```

Text (`_data/locales/<code>.yaml`, plain text, no HTML). English defaults live in `_data/ui.yaml`:

```yaml
ui:
  shared:
    translationNotice:
      ai:
        message: This page was translated by AI.
        originalLink: Read the original
```

### Language switcher (top right)

A toggle next to the theme controls replaces the in-page switcher. With two languages it links to the other language; with more it opens a small menu. Pages with a counterpart link to it; pages without one link to the other language's home.

```yaml
# _data/site.yaml
i18n:
  languages:
    - code: en
      label: English
      shortLabel: EN      # toggle label; falls back to label, then the uppercased code
    - code: zh
      label: 简体中文
      shortLabel: 中文
```

Accessible name: `ui.shared.languageSwitcher.label` (English default `Language`, overridable in `_data/locales/<code>.yaml`).

The notice `message` keeps its line breaks: newlines become `<br>` (trimmed and escaped), with the original link at the end of the last line.
